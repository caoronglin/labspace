# 深度研究编排

## 何时使用

- 问题包含多个子问题，单次检索无法回答。
- 需要比较多个物种、方案或数据集，并给出有依据的结论。
- 用户明确要求「深度研究」「系统调研」「写综述」。

## 三层角色（同一会话内完成）

1. **总目标（Overall）**：先用一句话复述研究问题，列出 2-到 4 条验收标准，例如覆盖哪些物种、需要哪类证据、输出形式。
2. **任务拆解（Mission）**：拆成 3 到 6 个可独立完成的任务，标注依赖关系与所需工具。
3. **执行（Worker）**：逐项调用工具取证；每完成一项立即更新进度，不跳步、不并行猜测。

信息不足时最多追问 2 个关键问题（研究范围、验收标准），其余按合理默认继续并在结论中说明假设。

## 研究板

- 开始前先输出一张 Markdown 表：`编号 | 任务 | 工具 | 状态 | 产出`。
- 每一轮回答开头更新状态（待办 / 进行中 / 完成 / 受阻）；受阻必须写明原因与替代路径。

## 取证规则

- 实验室知识库优先：`lab_knowledge_search`。
- 专业数据库：`lab_database_query`，一次只查一个库，参数遵循 `plant-database-search` 技能。
- 外部资料：`lab_web_search`；文献结论必须给出来源。
- 内部服务能力：`lab_services`。
- 不补写工具没有返回的事实；证据冲突时并列呈现并说明强弱。

## 复核（Review）

提交结论前逐条自检：

- 每个关键结论是否有来源或数据支撑？
- 验收标准中的每一项是否都已回答？
- 是否混淆了相关性与因果、物种 / 版本 / 坐标 / 基因组版本？
- 不确定的结论是否标注了置信度与验证方法？

## 沉淀

- 经用户确认后，用 `lab_knowledge_save` 保存可复用结论或方法，默认 private，不自动公开。
- 后续实验步骤用 `lab_workbench_capture` 写入个人工作台；同一任务不要重复记录。

## 输出结构

1. 结论摘要（3 到 5 条，每条带证据）
2. 研究板最终状态
3. 证据与来源（逐条链接或登录号）
4. 局限与下一步建议
